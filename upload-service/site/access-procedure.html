MAHA · ADMIN PROCEDURE · 4 NOVEMBER 2026

Grant and remove access.

Use this procedure from the Users page while signed in as a Super user. Save progress there after each step. The library and the router’s VPN are separate systems.

Reference settings

Library
https://192.168.1.64/ — same address at home and through the VPN.
Router administration
http://192.168.1.1/ → Advanced → VPN Server → WireGuard.
Router
TP-Link Archer BE550 v1.0. WireGuard server tunnel 10.5.5.1/32; UDP port 51820; Home Network Only; up to 16 profiles. The first owner phone uses 10.5.5.2/32.
VPN peer endpoint
vpn.discerntechnologies.com:51820. MAHA’s independent DDNS service checks the current public IP every five minutes. Don’t hard-code the current public IP in new client profiles.
Library roles
User: browse, search and read. Super user: manage books, users and invitations. A library role does not limit the rest of the home network.

1. Save an access plan

  1. Open Users → Start someone’s setup.
  2. Enter the person’s email, choose User unless management access is required, and choose at-home-only or remote access.
  3. Click Start / resume setup. This saves a plan; it does not send email or configure the router.
  4. For an existing account, save the plan and record additional devices; don’t create another account for each device.

2. Create a router profile for each remote device

  1. Skip this section for local-only access.
  2. Open the router’s WireGuard Account List and click Add. Use a unique profile name such as Alex-Phone.
  3. Keep the new device address assigned by the router. Never reuse another active device’s address. A phone and a laptop require separate profiles.
  4. For library-only routing, use 192.168.1.64/32 for Allowed IPs (Client). Keep Allowed IPs (Server) at the new device’s assigned address, for example 10.5.5.3/32. Client routing is not enforced network isolation.
  5. Save; export the configuration or scan the QR code directly on the intended device using the WireGuard app.
  6. Confirm the client’s peer Endpoint is vpn.discerntechnologies.com:51820. Leave its keys and assigned address unchanged.
  7. Deliver the configuration privately, not in a public email or screenshot. Record the exact profile name, address and delivery progress in the Users device checklist. Never put private keys or QR codes in the library’s tracking fields.

The web server accepts the configured 10.5.5.0/24 VPN range after this workflow update. It is the router’s responsibility to authenticate VPN devices. Broader distribution to people who should not have home-network access requires additional network isolation.

3. Supply the public HTTPS certificate

  1. Use Download public MAHA certificate in the access workflow. This downloads only the public CA certificate, not a private key.
  2. Send the public certificate with the setup instructions. Installing it means the device trusts certificates issued by MAHA’s CA. Verify its fingerprint through your trusted administrator before installing.
  3. Windows: import it into the current user’s Trusted Root Certification Authorities store.
  4. Android: Settings → Security / More security settings → Encryption & credentials → Install a certificate → CA certificate. Select the file.
  5. iPhone/iPad: install the downloaded certificate profile in Settings, then enable full trust under General → About → Certificate Trust Settings.
  6. Menu names vary. Do not bypass certificate warnings. Devices need this trust setup once.

4. Create and send the library invitation

  1. Choose the invitation’s role and click Create invitation. Replacing a pending invitation invalidates its previous link.
  2. Click Email invitation & instructions. This opens your email app; attach the public certificate and send the prepared message there. Send VPN credentials privately.
  3. The link expires in seven days and can be accepted once. It is shown only when generated; create a replacement if it was lost.
  4. The recipient trusts the certificate first, connects to the home network or VPN, opens the invitation, and creates their own password of at least 12 characters.
  5. After accepting the invitation, they sign in using the invited email and their password. Invitations do not themselves grant VPN access.

5. Verify and record completion

  1. For a remote phone, turn Wi-Fi off, use cellular data, and enable WireGuard.
  2. Open https://192.168.1.64/, sign in and open a book. There should be no certificate warning.
  3. For a User, verify account management and uploading are unavailable.
  4. Record completion in the device checklist. The checklist records your confirmation; it is not live router telemetry.

6. Revoke access

  1. Select the person and click Disable library access & flag VPN removal. This disables library login, revokes sessions and cancels outstanding invitations immediately. The last active Super user is protected.
  2. Open the router’s WireGuard Account List and remove each recorded profile belonging to the person or lost device. Disabling the library account alone does not revoke VPN network access.
  3. In each device checklist, mark “I deleted this profile on the router.” Keep the entry as history.
  4. For a lost device only, remove its router profile and flag that device; the person’s other profiles can remain.
  5. To grant access again, explicitly re-enable the library account if appropriate and create a new VPN profile/device record. Do not mark a removed profile active again.

Troubleshooting

  • No handshake: check cellular connectivity, endpoint name/port and that the router profile still exists. Dynamic IP updates can take several minutes; reconnect the tunnel to resolve the endpoint again.
  • Handshake but 403: confirm the assigned VPN address and Nginx allow rules. Don’t open the library directly to the internet.
  • Certificate warning: verify and install the correct MAHA public CA. Check the URL and device date. Don’t bypass the warning.
  • Invitation expired: a Super user creates a replacement and sends the new link.
  • Login page works but access fails: confirm the invited email and that the account is enabled. Readers cannot use Super user functions.

Keep these records safe

Workflow plans, devices and recorded actions are in the protected account database at /srv/maha-library-api/accounts.sqlite. Back it up consistently using SQLite backup or a stopped service. Securely back up /etc/maha-library/pki/, including its private keys, outside the public media tree. Router configuration/keys require a separate protected router backup. The web workflow never backs up or stores the router’s private keys.
